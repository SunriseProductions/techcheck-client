# Sunrise Tech Check 0.1.12

## What's new

- **See your own result.** When your tech check uploads successfully, the result screen now shows a **View your result** button that opens your report — verdict, locations tested, and map — in your browser, plus a **Copy link** button to share it (for example, paste it into an email). The link is valid for 24 hours. If you need a fresh link after that, ask IT.
- **Accurate packet loss.** Fixed a measurement bug that reported a constant ~2% packet loss on every location, even on a perfect connection. Loss is now counted from the pings that were actually sent, so a clean network reads as 0%.
- **About panel (macOS).** The app menu now has an **About Sunrise Tech Check** item showing the version and support contact.

## Internal

- The report-submission response now carries an optional `share_url`; the client renders it as-is when present and hides the block when absent (older servers that don't send it are unaffected). The link is never written to disk, logged, or sent in telemetry — it lives only in the running session. Opens via the system browser (`BrowserOpenURL`), copies via `ClipboardSetText`.
- Packet-loss fix: `MeasureJitter` dialed each ping against the window-end deadline, so the final ticker tick inherited a ~0ms budget, timed out, and was counted as a dropped packet — one phantom drop per ~46 attempts (~2.2%), independent of the real network. Pings now dial against the parent context (bounded by `Dialer.Timeout`). Loss is computed from the real attempt counts returned by `MeasureLatency`/`MeasureJitter` rather than a hardcoded theoretical total.
- macOS About panel built from `report.ToolVersion` (can't drift), embedding `build/appicon.png`, wired through Wails `Mac.About`.
- DMG **Read Me First** refreshed: it no longer describes the pre-notarisation "Open Anyway" Gatekeeper step, which notarised builds don't trigger.
